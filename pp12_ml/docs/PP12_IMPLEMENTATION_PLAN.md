# PP12 Implementation Plan

## Phase 1 - изолированный ML-контур

Статус: выполнено в рамках текущей задачи.

Задачи:

- Создать папку `pp12_ml` без изменения WPF-проекта.
- Добавить документацию по цели, архитектуре и ограничениям.
- Подготовить датасет строительных задач на 6 категорий.
- Добавить notebook для обучения классификатора по названиям задач.
- Добавить FastAPI-сервис с endpoint-ами:
  - `GET /health`
  - `POST /predict-category`
  - `POST /generate-description`
- Добавить prompt builder с учетом категории и похожих примеров.
- Добавить LM Studio client для локального endpoint.
- Добавить Dockerfile и requirements.

## Phase 2 - обучение и проверка

Задачи:

- Запустить notebook полностью в локальном окружении.
- Проверить качество `LogisticRegression` и `LinearSVC`.
- Сохранить артефакты:
  - `artifacts/best_model.joblib`
  - `artifacts/tfidf_vectorizer.joblib`
  - `artifacts/label_encoder.joblib`
- Проверить `/predict-category` на контрольных примерах.
- Проверить `/generate-description` без LM Studio и с включенным LM Studio endpoint.
- Подготовить скриншоты notebook, API-запросов и результата генерации для отчета.

## Phase 3 - интеграция с WPF

Задачи:

- Добавить в WPF настройку адреса PP12 ML-сервиса.
- Изолировать C# HTTP-клиент для вызова нового сервиса.
- Подключить сервис к текущему действию `AI-описание`.
- Сохранить fallback на текущую LM Studio-логику или предусмотреть режим отключения.
- Добавить минимальные проверки ошибок сети и таймаутов.

## Основные риски

- Малый датасет может давать нестабильную классификацию для редких формулировок.
- LM Studio API в текущем C#-коде использует локальные endpoint-ы `api/v1/models`, `api/v1/models/load`, `api/v1/chat`; формат может отличаться от OpenAI-compatible endpoint в разных версиях LM Studio.
- WPF-приложение работает на .NET Framework 4.7.2, поэтому интеграцию лучше делать через простой HTTP JSON-контракт.

## Критерии готовности Phase 1

- Все новые файлы находятся внутри `pp12_ml`.
- Датасет содержит минимум 150 строк и 6 категорий.
- Notebook не пустой и содержит полный путь обучения, оценки и сохранения модели.
- Сервис содержит рабочие endpoint-ы и структурированные Pydantic-схемы.
- Dockerfile собирает FastAPI-сервис на Python 3.10+.
